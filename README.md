# Magnat

Nuxt + Supabase на сервере, Tauri-оболочки для Windows, macOS Apple Silicon, Android и iOS.

## Обновление сайта и приложений

Новые оболочки 0.2.3 открывают `https://192.168.10.250/?native=1&appVersion=0.2.3`. Интерфейс хранится на сервере,
а не в установщике. Пересборка и перезапуск контейнера Nuxt доставляют изменения на сайт
и в приложения. Изменения схемы Supabase требуют применения миграций.
Адрес сервера должен оставаться постоянным и доступным устройствам (для локального IP
настройте постоянную аренду DHCP в вашей сети).

При повторном открытии оболочка загружает актуальную страницу. Уже открытая оболочка
проверяет `/api/app-version` раз в 30 секунд и при возврате в приложение. После изменения
сборки страница перезагружается в состоянии покоя. Фокус в поле ввода, открытый диалог и
несохранённые изменения в полях откладывают перезагрузку до закрытия формы/смены раздела.
Ошибки запроса во время перезапуска сервера не показываются пользователю; проверка повторяется.

Автоматической установки обновлений оболочки нет. В меню приложения под «Копия личного хранилища» доступна страница «Версия приложения»: установленная версия, актуальный релиз и переход к загрузке. При запуске устаревшей версии появляется окно «Перейти и скачать / Позже / Закрыть». Новые установщики нужны при изменении
Tauri, Rust/нативных плагинов, разрешений ОС, иконок, версии оболочки или адреса сайта.
Для перехода со старой версии со встроенным интерфейсом нужно один раз установить новую оболочку.
При первом запуске после смены адреса загрузки может потребоваться повторный вход в аккаунт.

Оболочка разрешает сайту только явно перечисленные нативные действия: открытие ссылок, сохранение файлов, уведомления и чтение установленной версии. Веб-приложение работает с теми же
серверными API и проверками доступа, что и браузер. Для сборок с HTTP в локальной сети на Apple-платформах
есть ATS-настройки локальных соединений, на Android — исключение только для хоста сервера.
Android 17+ запрашивает разрешение доступа к локальной сети.

## Вход по QR-коду

На настольном экране входа справа от формы расположен QR-код. Обычная камера телефона
открывает `/auth/qr`; страница предлагает открыть Magnat через `magnat://auth/qr`,
а при отсутствии приложения остаётся доступен вход и подтверждение в браузере.
Обработка ссылок требует оболочки 0.2.3 или новее. В локальной сети вместо Universal Links
используется собственная схема: браузер может запросить разрешение на открытие приложения
или потребовать нажатия «Открыть в приложении Magnat».

Телефон должен быть авторизован. Пользователь сверяет шестизначный код и подтверждает
конкретное устройство; компьютер получает новую независимую сессию. QR действует две минуты,
обновляется кнопкой и используется один раз. Переход по ссылке сам по себе не подтверждает вход.
Секрет получения сессии остаётся на компьютере; в QR передаётся отдельный секрет подтверждения
во фрагменте ссылки. В таблице `qr_login_requests` (миграция 039) хранятся только хеши секретов,
чтение и запись доступны только серверу. Истёкшие запросы удаляются при создании следующего QR.
`MAGNAT_SERVER_URL` задаёт адрес QR-ссылок, доступный телефону, в том числе при открытии сайта
на компьютере через localhost. Телефон должен иметь доступ к этой сети и доверять сертификату сервера.

Проверка типов: `npm run typecheck`. При проверке QR-сценария проверьте подтверждение и
отклонение входа, истечение срока, повторное использование и независимость сессии компьютера.

## Сборка оболочек

`MAGNAT_SERVER_URL` — постоянный HTTP(S) origin. Текущий выбранный адрес — HTTPS на внутреннем IP. Клиентам Windows, macOS и iOS нужно доверять офисному CA из `deploy/windows-server/magnat-root.crt`; для Android он включается в сборку переменной `MAGNAT_ANDROID_CA_CERT` только для хоста сервера.
`MAGNAT_IOS_TEAM` — идентификатор существующей команды Apple для подписи iPhone-приложения.
Версия оболочки хранится в `src-tauri/tauri.conf.json` и `src-tauri/Cargo.toml`.

```sh
npm run macos:build
npm run windows:build          # внутри Windows
npm run android:release       # release APK с постоянным keystore
npm run ios:build -- --export-method debugging
```

Сборки не запускают Nuxt generate: `frontendDist` — URL сервера. `scripts/shell-config.mjs`
проверяет origin, создаёт конфигурацию удалённой страницы и отключает updater-артефакты.
`scripts/prepare-shell.mjs` создаёт платформенную конфигурацию для CI и iOS.
`npm run android:build` оставлен для debug APK; публичные загрузки используют release-вариант.

Мобильные иконки — существующий красный логотип Magnat из `public/favicon.svg`.
Обновляйте `src-tauri/icons`, `gen/android/app/src/main/res/mipmap*` и
`gen/apple/Assets.xcassets/AppIcon.appiconset` вместе при изменении логотипа.

## Отдельный workflow установщиков

`.github/workflows/release.yml` запускается вручную или при изменении нативных файлов
`src-tauri/**` и скриптов сборки оболочки в main. Изменения обычных страниц Nuxt, CSS,
серверных API и Supabase не запускают сборку установщиков.
Последовательность: Windows → macOS → Android → iOS → публикация.
В админке **Версии приложения** укажите следующую версию оболочки и описание для страницы загрузок.
После публикации версия неизменяема; следующий выпуск должен иметь больший номер.

Нужны self-hosted runners с меткой `magnat-ssd`: Windows и macOS. Node 24.15+, Rust 1.90+,
Windows C++ Build Tools/MSVC, Xcode/iOS SDK, Android SDK/NDK/JDK должны быть подготовлены.
Оба runner должны видеть одну папку релизов на SSD (Windows VM — через общую папку диска).
Рабочий каталог runner, `CARGO_HOME`, `CARGO_TARGET_DIR`, `RUSTUP_HOME`, `GRADLE_USER_HOME`,
`NPM_CONFIG_CACHE` и `TMPDIR` размещаются на SSD и проверяются `scripts/release-storage.mjs`.
На Windows `TEMP` и `TMP` тоже должны указывать на SSD.
Для Android дополнительно задаются `ANDROID_HOME`, `NDK_HOME`, `JAVA_HOME`.

Variables GitHub: `MAGNAT_SERVER_URL`. Secrets: `RELEASES_BUILD_TOKEN` (тот же, что
`NUXT_RELEASES_BUILD_TOKEN` на сайте), `ANDROID_KEY_BASE64`, `ANDROID_KEY_ALIAS`,
`ANDROID_KEY_PASSWORD`, при отдельном пароле хранилища `ANDROID_STORE_PASSWORD`.
Закрытые ключи и keystore не хранятся в Git. Постоянный keystore нельзя терять или менять
между версиями Android. Подпись updater больше не требуется.

CI сохраняет iOS-архив без подписи для разработчика. Установка на iPhone выполняется отдельно
с Apple Development-подписью и зарегистрированным устройством. IPA для такого устройства не
является универсальной установкой из App Store. Профиль имеет срок действия Apple.

## Страница скачивания и SSD

`/downloads` доступна без входа. Backend читает завершённый релиз из `NUXT_RELEASES_DIRECTORY`.
В Docker `.env` задаёт `MAGNAT_RELEASES_DIR` как путь на хосте, а
`NUXT_RELEASES_DIRECTORY=/releases`; папка монтируется в контейнер только для чтения.
Для админского плана релиза применяется миграция `026_app_releases.sql`.

```text
releases/
  latest.json
  0.2.0/
    release.json
    Magnat-0.2.0-windows-x86_64.exe
    Magnat-0.2.0-macos-aarch64.dmg
    Magnat-0.2.0-android-arm64.apk
    Magnat-0.2.0-ios-device.ipa   # только если подписан для зарегистрированного устройства
  .staging/
```

Новая версия становится доступна после проверки всех пакетов и атомарной смены `latest.json`.
Предыдущие версии сохраняются на SSD. Если диск отключён, backend не создаёт папку на внутреннем
диске вместо него. Для повторного запуска CI используйте Re-run all jobs.
